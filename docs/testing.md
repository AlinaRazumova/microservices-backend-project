# Testing Guide

This guide describes how to verify the system manually using Swagger UI.

## 1. Start the project

```bash
docker compose up --build
```

Available services:

- Auth Service: `http://localhost:8001/docs`
- Task Service: `http://localhost:8002/docs`
- Notification Service: `http://localhost:8003/docs`
- React Client: `http://localhost:3000`

## 2. Register the first user

Open Auth Service Swagger and use:

```text
POST /auth/register
```

Request body:

```json
{
  "email": "admin@example.com",
  "username": "admin",
  "password": "admin123"
}
```

Expected result:

```json
{
  "id": 1,
  "email": "admin@example.com",
  "username": "admin",
  "role": "admin"
}
```

The first registered user becomes `admin` automatically.

## 3. Log in

Use:

```text
POST /auth/login
```

Request body:

```json
{
  "email": "admin@example.com",
  "password": "admin123"
}
```

Expected result:

```json
{
  "access_token": "...",
  "token_type": "bearer"
}
```

Copy only the token value.

## 4. Authorize protected endpoints

In Swagger, click `Authorize` and paste only the token value.

Do not add `Bearer` manually. Swagger adds it automatically.

## 5. Check current user

Use:

```text
GET /auth/me
```

Expected result: current logged-in user data.

## 6. Create a task

Open Task Service Swagger and authorize using the same token.

Use:

```text
POST /tasks
```

Request body:

```json
{
  "title": "Prepare project presentation",
  "description": "Create final presentation for microservices backend project",
  "status": "todo",
  "priority": "high",
  "deadline": "2026-05-20T23:59:00",
  "assigned_to": 1
}
```

Expected result: created task with an `id`, `owner_id` and `assigned_to`.

## 7. List tasks

Use:

```text
GET /tasks
```

Expected result: list of visible tasks.

## 8. Filter tasks

Filter by status:

```text
GET /tasks?status=todo
```

Filter by priority:

```text
GET /tasks?priority=high
```

Search by title or description:

```text
GET /tasks?search=presentation
```

Combined filtering:

```text
GET /tasks?status=todo&priority=high&search=project
```

## 9. Update a task

Use:

```text
PUT /tasks/{task_id}
```

Example request body:

```json
{
  "status": "in_progress"
}
```

Allowed statuses:

- `todo`
- `in_progress`
- `done`
- `cancelled`

Allowed priorities:

- `low`
- `medium`
- `high`

## 10. Assign a task

Use:

```text
PUT /tasks/{task_id}/assign
```

Request body:

```json
{
  "assigned_to": 1
}
```

## 11. Delete a task

Use:

```text
DELETE /tasks/{task_id}
```

Expected result:

```json
{
  "message": "Task deleted successfully"
}
```

## 12. Test notifications

Open Notification Service Swagger and authorize using the same token.

Use:

```text
GET /notifications
```

Expected result: notifications generated by task creation, assignment or status change.

Mark notification as read:

```text
PUT /notifications/{notification_id}/read
```
